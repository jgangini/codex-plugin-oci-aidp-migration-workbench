# v0.1.16 — Reproducible AIDP diagnostics and validation

Irregular migration runs need evidence that separates processing, driver waits, data differences and incomplete telemetry. This release consolidates the tested local diagnostic procedures into the public plugin without shipping customer notebooks, runtime credentials or case exports.

## Changes

- Two dependency-free offline helpers decode actual AIDP output and assess comparable full-run series. They preserve original evidence, reject overwrite, validate inputs and distinguish execution repeatability, correctness and operational verdicts.
- Output decoding handles notebook output cells, nested APPLICATION_JSON, text fragments, adjacent JSON events and the specific AIDP command-failure signal even when the surrounding kernel reports success. Unknown/truncated shapes are rejected rather than treated as clean evidence.
- Repeatability requires complete unrepaired runs, distinct attempts, chronological continuity, matching input/code/workflow/effective configuration fingerprints and cold/warm/cold behavior. It reports min/median/max and population CV without imposing a fixed two-hour limit. Prior complete diagnostic evidence can qualify without rewriting launch metadata.
- Spark/Volume guidance covers complete producer barriers, inventory comparison, URI consistency, commit latency, filesystem mkdirs compatibility, independent writer salts, file-growth bounds, single-partition native markers, scoped cache release, Observation attribution, listener pressure and duplicate-selection nondeterminism.
- Versioned experiment journals, bounded log collection, interrupted-monitor reconciliation, full result comparisons, ordered `99_report` SQL guidance and provisioned-time cost accounting connect deployment, runtime validation, recovery and acceptance.
- Streaming recovery retains existing job identities and durable checkpoints, distinguishes progress from a RUNNING state, and requires offsets/backlog/committed-output parity. It remains separate from any explicitly scoped reset.
- Oracle's Workbench Engineer Agent stays a separate upstream plugin. Guidance requires version/provenance and API/target compatibility checks; no Oracle implementation is redistributed or patched here.
- Architecture wrappers now save/check the structural baseline even when no custom rules file exists, propagate failures and explicitly report when Graphify is not configured.

## Validation

- Existing run-summary regression checks passed: repairs/current attempts, timing, redaction, invalid input and overwrite protection.
- New synthetic diagnostic checks passed: separate verdicts, immutable comparison identities, missing evidence, repair/manual-intervention rejection, invalid/overflow timing, output-only parsing, command failures, concatenated/truncated events and CLI round trips.
- The decoder was also checked against an existing restricted AIDP export. The export and its contents are not part of this release.
- Official plugin validator and all 11 skill validators passed. The reusable scripts require only Python's standard library; PyYAML was used solely by the external packaging validator.
- Graphify is not configured in this repository. No claim of Graphify coverage is made.
- Sentrux was run before and after changes. There are no dependency cycles, god files or complex-function increases. The aggregate quality signal decreased, and the structural gate reports that decrease rather than a pass. This is an intentional, documented tradeoff: the formerly almost-disconnected script graph now includes explicit imports from regression checks into two focused utilities and reuses the existing digest helper. The initial complex functions were reduced. No baseline was reset, test imports removed or files excluded to hide the signal. No custom Sentrux rules are configured.

## Evidence limits

The live campaign informed the diagnostic mechanisms and safe experiment design; its complete business-result reconciliation was still in progress at the release evidence cutoff. No workload is declared universally fixed, stable or certified by shipping this plugin. Reading metadata successfully does not establish row parity or a faster full run. Queue changes, writer limits and partition counts are case-specific experiments, never global defaults.

The release performs no automatic cloud changes, cluster starts, data resets, checkpoint deletion, vendor JAR modifications, ARM comparisons, Slack messages or support escalation. Existing user authorization is reused within its scope; publication of case evidence requires its own authorization.
